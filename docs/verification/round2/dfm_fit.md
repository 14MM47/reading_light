# Verification round 2: PCB DFM, fab package and mechanical integration

Reviewer: independent DFM / fab-package and adversarial mechanical-integration review. Date 2026-11-02.
Repo `/home/user/reading_light`, branch `claude/great-shannon-bikrur` @ `15d1f96` (clean). Nothing in the repo was edited.
Scratch work (scripts, renders, DRC re-runs): `/tmp/claude-0/-home-user/7ba8e87c-d4ee-5a66-9891-51bde4e0a9a7/scratchpad/review2/`.

**Method.** Gerber/drill files were read directly (apertures, G85 slots, outlines). The two `.kicad_pcb` files were
loaded read-only with `pcbnew`, which gave pad geometry, nets, zone fills, radial extents, mask webs and via-in-pad.
DRC was re-run on a scratch copy of the LED board with 0.2 mm clearance. Layers were rasterised with `kicad-cli pcb
export pdf`, and the assembly PDFs and renders were inspected. Datasheet land patterns were rendered from the PDFs
in `scratchpad/ds/`. Print STLs were parsed with numpy to get vertex extents and connected components. Packlib and
moonlib values came from the `cad/parts` sources.

**Result: 3 BLOCKER, 3 MAJOR, 12 MINOR, 7 NOTE.** The gerbers themselves would be accepted by PCBWay. What fails:
- The main board's battery-lead slot cannot pass the battery's plug (a PCB change, so do it before ordering).
- The printed back plate cannot be fitted into the front shell.
- The gooseneck thread end is not controlled against the LED board.
- The RGB LED polarity instructions are wrong, so Matt could fit both RGB LEDs rotated.
